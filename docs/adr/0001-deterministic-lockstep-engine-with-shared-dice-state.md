# 0001. Deterministic lockstep engine with dice drawn from shared state

## Status

Accepted

## Context

A cross-device match must play out identically on every phone at the table, with no server and no internet connection to arbitrate disagreements. Three ways to keep devices in sync were on the table: ship the full game state after every turn, ship each device's locally computed result and trust it, or ship only the actions players take and have every device recompute the outcome itself.

Full-state sync wastes bandwidth on a board that barely changes turn to turn and gives a malicious or buggy client room to inject an arbitrary state. Trusting each device's computed result is worse: a modified client could simply report the roll it wants.

## Decision

We recompute everywhere from a log of actions (option c). The engine is a pure reducer over match state. A seeded PRNG (xoshiro128**) is carried as part of that match state itself — never read from `Math.random()`, the system clock, or any other ambient source. Dice values are drawn from this shared stream during action resolution, not generated by the rolling client and sent across.

## Consequences

A turn now costs a few hundred bytes of action data instead of a full board snapshot, and a tampered client cannot roll itself a favorable number because it never produces the number — the shared stream does, identically on every device that resolves the same action in the same order.

The cost is that any source of non-determinism anywhere in the engine — object key iteration order, floating-point rounding that differs by platform, a stray `Date.now()`, an unordered array sort — will silently desync devices with no error message, just a board that quietly diverges. We guard against this by fuzz-testing the engine: replaying randomly generated matches on two independent engine instances and asserting the resulting states are byte-identical. It also means a device that misses an action in the sequence cannot recover by asking a peer "what is the current state?" — there is no authoritative snapshot to hand over. It must replay the action log from the point it has.
